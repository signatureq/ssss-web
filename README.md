# ssss / web developer

Персональный сайт-визитка о веб-дизайне и разработке. Заявку можно оставить через форму с именем, почтой и описанием проекта; альтернативный контакт — Telegram [@added08](https://t.me/added08).

Основной домен: [ssss-web.ru](https://ssss-web.ru/). Хостинг — GitHub Pages.

Актуальный репозиторий сайта и настроек Pages — `signatureq/ssss-web`. Репозиторий `signatureq/ssss-web-developer` содержит предыдущую версию; Pages в нём отключён.

Визуальное направление вдохновлено midu.design. Вёрстка, тексты, графика и WebGL-эффект написаны для этого проекта; чужие работы и отзывы не используются.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Сайт откроется на http://127.0.0.1:5173/.

## Сборка

```sh
npm run build
npm run preview
```

Папка `dist` — готовая статическая версия.

## Публикация

GitHub Pages автоматически обновляется после push в `main`. Workflow `.github/workflows/deploy.yml` устанавливает зависимости, собирает сайт и публикует `dist`.

Сборка для собственного домена использует корневой путь `/`:

```sh
npm run build
npm run preview
```

Локальная разработка остаётся на корневом пути `/`. В настройках репозитория Pages выбран источник GitHub Actions.

## Домен

В GitHub Pages указан Custom domain `ssss-web.ru`. В DNS-панели домена нужны следующие записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | signatureq.github.io |
| CAA | @ | 0 issue "letsencrypt.org" |

TTL — 3600 секунд или значение по умолчанию. После распространения DNS GitHub выпускает сертификат; в Pages нужно проверить состояние сертификата и Enforce HTTPS. При публикации через Actions отдельный файл CNAME не требуется.

### Проверка HTTPS

На 10 октября 2026 года публикация работает: HTTP возвращает `200 OK`. Четыре A-записи и `www` CNAME подтверждены через Google DNS, Cloudflare DNS и диагностический workflow на GitHub. DS-записей DNSSEC нет; до проверки CAA-записей тоже не было. При этом Pages health check возвращает `InvalidDNSError` и `caa_error: Dnsruby::ServFail`; HTTPS обслуживается сертификатом, не соответствующим домену. Однократная повторная привязка домена не устранила ошибку.

В REG.RU добавлена явная CAA-запись `@ 0 issue "letsencrypt.org"`, разрешающая выпуск сертификата центру GitHub Pages. Запись сохранена в панели, её распространение и выпуск сертификата пока не подтверждены. Отсутствие CAA само по себе не было ошибкой; запись добавлена для проверки сбоя CAA-запросов. Остальные записи и DNS-серверы не изменялись.

Это не ошибка сборки сайта. Следующий шаг — проверить доступность DNS-проверок GitHub к `ns1.reg.ru` / `ns2.reg.ru` и передать диагностику поддержке REG.RU или GitHub. Смена DNS-хостинга требует переноса всех записей зоны; не менять NS без сохранения зоны. После успешной DNS-проверки и выпуска сертификата включить Enforce HTTPS.

Диагностика: [запуск workflow от 10 октября](https://github.com/signatureq/ssss-web/actions/runs/37988676514). Настройки: [GitHub Pages](https://github.com/signatureq/ssss-web/settings/pages). Проверка API: `gh api repos/signatureq/ssss-web/pages/health`.

## Форма обратной связи

В блоке `#contact` посетитель может оставить имя, почту и описание проекта. Заявки отправляются на `anapa2007@macrowback.xyz` через [FormSubmit](https://formsubmit.co/documentation), без серверного кода на GitHub Pages. Telegram остаётся альтернативным способом связи.

В `index.html` находятся адрес получателя в `action`, тема письма `_subject="Новая заявка с сайта"`, шаблон `_template="basic"` и адрес формы `_url`. Поля передаются с русскими именами `Имя`, `Почта`, `Сообщение`, чтобы эти подписи использовались в письме. После первой отправки владелец почты должен открыть письмо FormSubmit и нажать **Activate Form**. Без активации FormSubmit не начнёт пересылать заявки. При смене получателя активацию нужно повторить. В письме подтверждения сервис также предлагает непрозрачный идентификатор для замены открытого адреса в `action`.

Владелец подтвердил активацию текущего получателя и прислал скриншот полученной первой тестовой заявки. Локальные тесты сами по себе доставку письма не проверяют.

Тема и пользовательские поля письма русские. Служебное вступление FormSubmit остаётся английским в его [готовых шаблонах](https://formsubmit.co/email-templates); в [штатных параметрах](https://formsubmit.co/documentation) настройка его перевода не описана. Текущая интеграция сохраняет FormSubmit и не обещает полного перевода служебного оформления.

С JavaScript запрос идёт на HTTPS AJAX endpoint FormSubmit, ответ появляется под кнопкой без перехода на другую страницу. Обработчик добавляет `_replyto` из поля `Почта`, чтобы ответ на письмо адресовался отправителю без отдельной английской строки `email`. На время запроса поля и кнопка заблокированы. Успешная отправка очищает поля; ошибка или тайм-аут сохраняет текст для повторной попытки. Автоматических повторов нет. Без JavaScript работает обычная отправка POST на FormSubmit с его страницей результата и русскими полями; `_replyto` в этом варианте не добавляется, поэтому адрес для ручного ответа нужно взять из поля `Почта`. Поле `_honey` добавлено для отсеивания спама; настройки CAPTCHA сервиса не отключаются.

Форма продолжает существующую контактную палитру и открытую компоновку. Локальные адаптации для доступности: граница поля `#807e75` имеет контраст 3.26:1 к бумажному фону `#e9e6dd`; более тёмный красный `#96331e` используется для ошибок и наведения на кнопку отправки (6.03:1 к тому же фону). Эти функциональные состояния не задают нового визуального направления.

`_url` использует текущий рабочий адрес `http://ssss-web.ru/#contact`. После исправления сертификата домена его следует сменить на HTTPS. Сам запрос к FormSubmit уже использует HTTPS; подключение формы не исправляет сертификат GitHub Pages.

Проверка сетевого контракта: `npm test`. Пять тестов используют локальный сервер и не отправляют письма: проверяют JSON-заявку, русские поля и `_replyto`, отказ сервиса, HTTP/JSON-ошибки и тайм-аут. Обработчик формы — `src/contact-form.js`.

## Состав

- `index.html` — тексты, блоки и ссылки.
- `src/style.css` — оформление и мобильная версия.
- `src/main.js` — плавный скролл, меню и переключение сцен.
- `src/contact-form.js` — отправка заявки и состояния формы.
- `src/hero-light.js` — медленно переливающийся WebGL-фон с плавной реакцией на мышь.
- `src/process.js` — геометрическая анимация блока с этапами работы.
- `public/fonts` — локальные шрифты Manrope, лицензия OFL.
- `public/portfolio` — скриншоты главных страниц четырёх проектов.

Vite, GSAP и Lenis. Отсутствуют аналитика, cookie-баннеры и внешние iframe. Форма передаёт введённые посетителем имя, почту и сообщение в FormSubmit для отправки заявки владельцу сайта. При `prefers-reduced-motion` движение отключается. Если WebGL недоступен, остаётся статичный фон.
